# P0 工程骨架与命令受理闭环

## 授权与依赖

用户于 2026-10-12 批准父任务最终方案，并批准从 P0 的工程骨架、中文规范工具链和首个命令受理/查询闭环开始。本任务是该已批准范围的可独立验收切片；依赖父任务的设计、中文规范与模板，无其他实现前置任务。父任务仍承担 V1 总体验收，不因本切片完成而视为整个 P0–P2 完成。

## 目标与变更边界

当前 Mousehole 只有 Trellis 文件，没有可运行产品。增加 Go API、PostgreSQL 持久化和 React 中文工作台，以合成项目的“创建任务草稿”验证完整数据流。代码位于 backend/、web/、api/；根配置、scripts/、deploy/、docs/ 和 CI 负责一致开发与验收。ARTEX 保持只读，不复制其实现。

仅开放显式 development 模式及 loopback 服务，使用固定本地开发身份适配器；不宣称已完成企业 OIDC。所有业务路由仍通过统一身份/项目边界。没有 Runner、目标访问、扫描、模型调用、Temporal 调度或真实执行能力，也不预建未实现模块。

## 验收

1. 能从中文页面创建任务草稿，查询服务端持久化回执；回执明确“已受理”，任务始终为 draft，不表示任何目标行为已执行。
2. 浏览器发送前生成 command_id；相同项目、ID 和参数并发提交只产生一份回执、草稿、审计和 outbox。同 ID 不同参数返回 409，已有记录不变。
3. 命令响应丢失时保留原 ID 并查询；暂未找到或网络错误显示受理待确认，不自动换 ID 重发。人工输入既有 ID 可在刷新后恢复查询，无敏感数据持久化。
4. PostgreSQL 在同一事务提交四类记录，失败整体回滚；进程重启后查询仍可恢复。集成测试真实连接 PostgreSQL，缺依赖明确失败，不 skip。
5. 请求/错误/状态源自 OpenAPI；生成前端类型/client 规则可复现。参数、未知字段、项目访问和幂等冲突有实际测试。
6. 手写注释与文档为简体中文，英文机器契约不变；格式、Go 静态检查、TS strict、lint、单元/集成、Web 构建与关键端到端检查有准确命令和实际结果。
7. 根 README、迁移说明、实际前后端 spec、PR 模板、CI 和依赖锁定与代码一致；工具未运行或检查受阻如实记录。
