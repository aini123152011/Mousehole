# 新平台统一中文代码编写规范

本文件是新平台的拟定工程规范，配套 [中文注释与文档模板](coding-templates.md) 和 [实施路线图](implement.md)。它回答代码怎么组织、怎么命名、哪里必须写注释、如何统一格式、怎样审查与验收。技术栈仍以 [设计方案](design.md) 的推荐为基础；最终选型时同步调整相关工具，不改变已确认的产品边界。

本规范形成于方案阶段，以下涉及完整平台的目录、命令和示例仍是后续约定，不能作为全部已实现或已通过测试的证明。用户批准后，首个草稿命令切片已开始落地；实际中文规范已同步到 [后端 spec](../../spec/backend/index.md) 与 [前端 spec](../../spec/frontend/index.md)，准确命令和验证结果见 [根 README](../../../README.md) 与 [验收记录](../../../docs/validation/p0-command-foundation.md)。

## 1. 执行原则与语言

“必须”是后续提交和审查的门槛；“建议”允许按实际模块解释取舍；“按需”仅在有需求或测量依据时采用。例外必须记录原因、范围、责任人和复核条件，不以整目录关闭检查代替说明。

| 对象                                               | 统一规则                                   | 示例                                     |
| -------------------------------------------------- | ------------------------------------------ | ---------------------------------------- |
| 手写代码注释、类型/接口说明、迁移说明              | 简体中文，必要时保留英文技术名词           | `Version 表示业务修订号，用于并发控制。` |
| README、ADR、接口描述、测试场景、PR 与操作手册     | 中文正文与中文标题，示例命令保留原语法     | `取消请求与停止确认`                     |
| 用户界面、校验提示、对外错误说明                   | 中文，使用统一领域词汇，不直接显示内部异常 | `任务状态已变化，请重新加载。`           |
| 标识符、包/文件名、API 路径、JSON 字段、数据库对象 | 规范英文，机器契约不随界面语言变化         | `TaskID`、`taskId`、`task_id`            |
| 状态值、错误码、事件名、日志字段、指标名           | 稳定英文，含义与版本有文档                 | `outcome_unknown`、`version_conflict`    |
| 第三方源码、许可证、生成标记、编译与工具指令       | 保留原文和固定语法，遵守来源许可           | `//go:generate`、`-- name:`              |

统一词汇：授权书 `AuthorizationLetter`、执行轮次 `Run`、行动 `Action`、执行尝试 `Attempt`、证据包 `EvidencePackage`、发现 `Finding`、复测 `Retest`、报告版本 `ReportVersion`。`Intent` 表达计划意图，`Action` 表达可判定的执行请求，两者不混用。中文“结果未知”对应 `outcome_unknown`；“已受理”不等于“已执行”，“请求停止”不等于“停止已确认”。后续领域词表放入新项目文档并与 OpenAPI、界面和状态机同步维护。

禁止把中文说明全部留到聊天记录中。关键约束必须存在于代码边界或有链接的权威文档里；示例与实现发生变化时同一提交更新。

## 2. 文件与排版

| 范围                                       | 格式权威与规则                                                                                            |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| 全部手写文本                               | UTF-8、无 BOM、LF、文件末尾一个换行、删除无意义行尾空白；Markdown 有意换行使用显式语法                    |
| Go                                         | `gofmt` 管排版，锁定版本的 `goimports` 管导入；使用 Go 工具生成的 tab 缩进，不套用前端空格规则            |
| TypeScript、TSX、CSS、JSON、YAML、Markdown | 推荐统一 Prettier：2 空格、分号、JS/TS 单引号、尾逗号、目标行宽 100；JSON 仍是双引号，具体输出服从 parser |
| ESLint                                     | 检查正确性、Hooks、导入边界和质量；不与 Prettier 重复争夺排版，采用兼容配置                               |
| SQL                                        | PostgreSQL 方言、关键字大写、对象小写 `snake_case`、参数化；格式器先验证 sqlc/迁移指令兼容性，再固定版本  |
| 文档                                       | 中文标题，代码块声明语言，表格含表头，列表前留空行；真实文件、接口或 ADR 使用可解析链接                   |

目标行宽是可读性提示，不要求为 Go 签名、URL、机器指令强行断行。CI 检查格式，开发者在本地运行相同配置自动修复。只格式化本次触及的文件；独立的大规模格式整理单独提交，便于审查行为变更。生成与第三方目录使用明确且最小的忽略规则。

换行由 `.editorconfig` 和 `.gitattributes` 一起约束，避免 Windows 与 Linux 来回改写。包管理器建议前端统一 pnpm，固定 Node/pnpm 版本并提交唯一 lockfile；Go 提交 `go.mod`、`go.sum`。工具使用与运行环境相匹配的受支持版本及精确补丁锁定，不在规范里长期写死“最新版”。

## 3. 命名与组织

| 内容             | 规则                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------- |
| Go 包            | 短小英文小写，按业务职责命名；避免万能 `common`、`utils`、`manager` 包                   |
| Go 文件          | `snake_case.go`，测试 `_test.go`；平台专用文件遵守 Go 后缀规则                           |
| Go 导出符号      | `PascalCase`；缩写使用 `ID`、`HTTP`、`URL`、`API`，如 `TaskID`                           |
| Go 私有符号      | `camelCase`；接口由消费方定义最小职责，命名说明能力，避免无意义 `I` 前缀                 |
| 前端文件/目录    | `kebab-case`，如 `action-timeline.tsx`、`use-task-events.ts`；工具强制入口名保留原样     |
| React / TS       | 组件、类型 `PascalCase`；变量/函数/属性 `camelCase`，如 `taskId`；Hook 以 `use` 开头     |
| 常量             | Go 使用惯用导出名；TS 固定配置/枚举常量可用 `UPPER_SNAKE_CASE`；禁止把所有变量伪装成常量 |
| API / 数据库     | 路径及字段遵循统一英文契约；JSON 和数据库列用 `snake_case`，URL 路径用小写连字符         |
| 布尔、集合、单位 | 表达肯定含义，如 `isExpired`、`canPause`；切片/集合用复数；数值声明单位，如 `timeout_ms` |

推荐最初采用单仓库，Go 控制面模块化、Web 按业务特性组织。以下为结构建议，只有实现需要时才创建文件：

```text
api/
  openapi.yaml                  # 对外契约与中文字段描述
backend/
  cmd/{api,workflow-worker,runner}/
  internal/
    {identity,authorization,asset,execution,evidence,finding,audit,eventing,model}/
    workflow/                   # Temporal 编排，调用领域服务 Activity
    runner/                     # 独立执行能力，不访问控制面数据库
    platform/                   # 有明确边界的数据库、对象存储等基础设施
    store/sqlc/                 # 只存放生成的数据库访问代码
  db/{migrations,queries}/
  go.mod
  go.sum
web/
  src/
    app/                        # 路由、Provider、应用组装
    features/{tasks,findings,evidence,approvals,scope}/
    components/ui/              # shadcn 基础控件与来源记录
    components/business/        # 经验证可跨特性复用的业务组合
    api/generated/              # OpenAPI 生成 client
    lib/                        # 有单一职责的跨特性工具
    styles/
  package.json
  pnpm-lock.yaml
docs/
  {architecture,api,runbooks,decisions}/
deploy/
  helm/
```

领域模块可包含 `domain.go`、`service.go`、`repository.go`、HTTP/存储适配器及邻近测试。传输层负责解码、身份、输入校验和响应；服务负责业务不变量及事务协调；存储适配器实现领域需要的接口。领域规则不能依赖 HTTP handler，Runner 不因共享源码而获得控制面数据库或长期机密权限。

前端特性内部再按 `components/`、`hooks/`、`api/`、`schemas/`、`types/` 划分，不预建空层。基础 `ui` 控件不发业务请求、不判断授权；业务组件和页面承担状态、组合与交互。共享抽象至少具有清楚的复用职责，优先特性内实现，避免为预测未来创建框架。

依赖跨模块通过明确接口或领域事件；禁止循环导入和隐式共享全局可变状态。限制文件大小时看职责和审查难度，不通过机械拆碎代码满足任意行数门槛。

## 4. 中文注释的覆盖要求

| 位置                          | 必须说明的内容                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| 核心 Go 包 `doc.go`           | 职责、数据权威、依赖方向和不能承担的职责；以 `Package 包名` 开头，正文中文                    |
| 手写 Go 导出符号              | 注释以符号名开头，说明含义；涉及行为时说明输入、结果及重要约束                                |
| 对外 TS 类型、业务组件与 Hook | TSDoc/JSDoc 描述作用和关键语义；真实需要时使用 `@param`、`@returns`、`@throws`                |
| 字段与枚举                    | 单位、可空/缺省含义、时间基准、版本、敏感级别、有效状态；直观且无额外语义的字段不逐一重复命名 |
| 复杂内部函数                  | 前置条件、业务原因、不变量、重要副作用和失败语义                                              |
| 并发/事务/授权/重试边界       | 锁与所有权、原子范围、幂等/重放、取消、未知结果和默认拒绝                                     |
| SQL 和迁移                    | 业务用途、排序/分页、锁、预期行数、部署顺序、兼容与回滚边界                                   |
| 配置、权限和特性开关          | 默认值、单位、生效方式、影响范围、秘密来源和危险变更行为                                      |
| 测试和运维脚本                | 为什么要验证该场景、预期结果、环境依赖及失败/恢复路径                                         |

注释解释“为什么、在什么条件下、失败会怎样”；不逐行翻译赋值、循环和显而易见的访问器。简单函数一两句足够，复杂业务边界才使用完整模板。源码中不要求作者、创建日期、修改流水；由 Git 和 PR 保存历史，避免头部失真。

`TODO` / `FIXME` 使用 `TODO(ISSUE-编号): 中文说明` 形式，说明完成条件；未有问题编号时在 PR 中关联跟踪项。影响授权、证据完整性、数据损失或执行正确性的未完成内容不能仅留 TODO 后宣称功能完成。禁止用注释代替错误处理或用“保证安全”掩盖尚未验证的假设。

保留许可证、生成器声明和工具固定语法。第三方保留内容不强制翻译；自持 shadcn 的新增说明与业务改动使用中文，记录上游来源、引入版本和本地差异，升级先审查差异。

## 5. Go 服务、并发与工作流

1. `context.Context` 作为需要上下文的函数首参，沿 API → 服务 → 数据库/Activity 传播。调用外部依赖设置预算内超时并及时 `cancel`；服务层禁止任意换成 `context.Background()` 丢失取消。启动与受控收尾的独立上下文需解释生命周期。
2. 返回错误保留原因，使用 `errors.Is/As` 和稳定类别判断。避免异常路径 `panic`、吞错、忽略资源关闭错误或层层重复记录；启动不可恢复配置错误由入口清晰失败。业务失败与取消、超时、结果未知分开。
3. goroutine 必须有所属生命周期、退出路径、错误传播及等待方式；channel 注明发送/关闭责任。共享可变状态说明锁、CAS 或事务保护及锁顺序；版本冲突和 fencing 拒绝有明确业务分支，不覆盖迟到结果。
4. PostgreSQL 拥有 Action/Attempt、lease、审批、业务事件与证据关联的权威状态；Temporal 拥有编排进度、timer、signal。状态机集中定义合法转换和条件，同一次状态变更、命令受理、必要审计与 outbox 原子提交。
5. 不在长期数据库事务内调用模型、网络目标、Runner 或上传对象。跨系统失败用显式状态、稳定 ID、幂等和 reconcile 收敛；证据 staging/上传与关联提交之间明确失败清理和孤儿对象处理。
6. Workflow 使用 SDK 的确定性机制；数据库、外部网络、系统时钟/随机数等不直接进入可重放 Workflow。Activity 明确 timeout、heartbeat、取消和重试策略，历史存引用与小状态。升级记录适用的兼容/版本策略，使用历史 replay 验证。
7. 向外部目标发起行为的适配器默认不自动重试。注释和能力目录说明可重放属性、幂等关联、上限与未知结果处理；旧 Runner 未隔离或前次结果未知时，不能仅凭超时重新发起。暂停/取消先是请求状态，只有停止确认后才显示对应完成含义。

不能在注释、测试或界面里声称目标请求 exactly-once、已发请求可撤回、签名可证明被攻陷 Runner 的结果真实。约束说明与 [设计方案的执行合同](design.md) 一致。

## 6. TypeScript、React 与 shadcn/ui

1. 推荐 TS `strict`，开启未检查索引与可选属性精确检查；以最终兼容配置为准。边界数据先 schema 校验，禁止 `any`、双重断言或非空断言绕过未知输入；必要第三方例外缩小范围并解释。
2. OpenAPI 生成类型/client 作为 HTTP 契约来源。传输字段保留生成的 `snake_case`，手写视图模型使用 `camelCase`；确有需要时在一个适配边界显式映射，禁止多页各自猜测字段、枚举或可空语义。
3. TanStack Query 管服务器数据；本地 React state 管组件交互，URL 管可恢复的筛选/排序/页和可分享视图。Zustand 仅按需管理偏好/布局，不再保存第二份服务器真相。Query key 必须包含项目、对象、筛选及分页身份，退出/切换权限时清理不适用缓存。
4. 请求使用库提供的取消信号，避免卸载后更新和旧响应覆盖新对象。SSE 统一接入，处理 durable cursor、重复/缺口、过期重快照和权限变化；hook 写明订阅、断开、回补和缓存刷新责任。只在事件已应用或相应权威刷新完成后推进客户端恢复位置；权限过滤可能造成可见序号不连续，不能仅凭 `seq + 1` 判断缺口，应遵循服务端恢复游标和过期语义。恢复完成后刷新权威数据，不把收到通知当作状态已成功变化。
5. 提交前生成稳定命令 ID/幂等键，保留参数绑定；受理响应丢失时按预先 ID 查询。关键命令状态区分提交中、已受理、执行中、确认完成、拒绝和未知；React mutation 网络失败不等于业务失败，不对未知目标行为自动重发。涉及授权、审批、取消与发现确认的 UI 不乐观伪造最终成功。
6. 表单统一 React Hook Form/Zod；服务端继续验证权限及业务约束。并发编辑按期望版本提交，冲突保留用户输入；敏感凭据、令牌和原始证据不进入 URL、持久草稿或 localStorage。
7. shadcn 作为基础控件层，统一设计 token、密度、焦点、中文状态文本与错误展示。组件 Props 用可判别联合表达互斥状态，避免多个布尔值组成不合法组合；列表和图共享领域 ID，不以数组下标作可变列表 key。
8. `loading`、`empty`、`error`、`stale`、`reconnecting` 有独立表现及最后同步时间。表格服务端分页/筛选/排序，批量操作声明作用范围，数量未知/截断明确提示；增量更新保留图视口和工作位置，按需展开并有列表替代。
9. 语义化 HTML、可见 focus、真实 label、键盘、弹窗焦点恢复和文本状态必须落实；颜色、图或 toast 不能成为唯一信息渠道。聚合实时更新后适度播报，不用每条 trace 淹没 `aria-live`。用户目标内容按不可信数据渲染，禁止未经隔离/净化直接注入 HTML；证据预览不自动执行或直接加载目标脚本/资源。
10. React Hook 文档只使用与实现相符的标签：异步状态由返回值表达时不要声称 `@throws` 同步抛出；依赖项、资源所有权和副作用由真实代码实现，注释不能修复失效的 effect。虚拟化、memo、复杂全局状态按测量需要引入。

## 7. API、数据与迁移

OpenAPI 每个业务端点描述用途、权限、授权/版本前置条件、参数单位、分页排序、成功/冲突/拒绝/未知响应和幂等规则；`operationId` 稳定且唯一。请求先完整校验再变更，未知工具/参数默认拒绝。命令查询每次重验身份/对象权限，相同幂等键不同参数拒绝；查询暂未找到不能推断外部行为必定未发生。

API 时间使用含 UTC 时区的 RFC 3339 字符串；持续时间注明单位。可能超出 JavaScript 安全整数的 seq、版本、计数或数据库 `int64` 在契约中明确采用十进制字符串，不在浏览器无损性未知时转换成 `number`。缺省、`null`、空字符串和空集合含义分别定义，分页使用稳定次序与唯一字段 tie-breaker；不声称动态列表一定具有精确总量。

SQL 参数化，sqlc 的 `-- name:`、结果基数和生成 schema 固定。状态更新检查合法前态/版本并处理受影响行数；唯一约束和事务承担最终并发保证，不能仅依赖“先查再写”。表/列敏感性、单位、保留与可空语义写入中文 schema 文档或 `COMMENT ON`。索引有对应查询和验证依据，避免为全部字段机械建索引。

编号 migration 不复用、不修改已发布版本。统一选择一种迁移工具，在落地阶段锁定；说明顺序、兼容范围、锁/耗时、回填、失败及回滚边界。采用 expand/contract，DDL 使用独立权限/Job。非事务 DDL、大表回填和有损变更显式标记；回滚分为可逆、需备份恢复或前向修复，不能承诺 down 脚本恢复已删除数据。

对象证据与报告不可就地覆盖，变更创建新版本并保留引用。Finding → Action/Attempt → Evidence 的来源、覆盖和授权信息不可被 UI/图投影替代；图为投影，报告固定原 finding/evidence/模板版本。原始证据访问、脱敏副本与保留处置各有明确接口。

## 8. 错误、日志与审计

对外错误采用稳定英文 `code`、中文 `message`、`request_id` 和按 schema 限定的安全详情。建议错误类别包含输入无效、权限拒绝、授权拒绝、版本冲突、依赖不可用、取消、期限到期；是否可重试由具体命令和 replay policy 判定，不给所有网络错误统一“重试”按钮。内部错误保留因果链，不匹配中文消息控制流程，不把 SQL/堆栈/秘密透给用户。

普通日志推荐 Go `slog` 结构化输出；稳定英文 `event` 和字段，中文说明。按需要记录 `request_id`、`project_id`、`run_id`、`action_id`、`attempt_id`、工具/策略版本、阶段、`duration_ms`、错误码。INFO 记录关键事实，WARN 记录可恢复异常，ERROR 记录责任边界失败；DEBUG 默认受控。低层返回、责任边界记录，避免每层重复堆栈。

日志、trace、指标、审计各有用途：审计保留真实 actor、对象、命令、授权/策略版本和决定，关键业务审计与状态同事务；运行日志不代替审计账本。OpenTelemetry 按数据分级传递上下文，指标禁止把目标 URL、对象 ID、错误正文等高基数/敏感内容做标签。排查秘密只展示密钥引用和脱敏元数据，不能临时开启全量敏感日志。

普通日志不写令牌、cookie、凭据、预签名 URL、完整请求/响应、原始证据、模型 prompt 或工具输出。确需受控调试/证据采集时走独立授权、脱敏、访问审计与保留通道。外部模型目的地和允许发送的数据级别由服务端规则判定，中文提示或脱敏注释不能替代实际校验。

## 9. 测试与测试注释

测试围绕可观察行为和不变量设计，变更只运行相关而充分的检查，不为注释、纯格式改动新增镜像实现测试。Go 测试函数英文，如 `TestAcceptCommand_SameKeyDifferentPayload`；子场景、Vitest/Playwright 用例说明及测试意图可写中文，断言失败信息应能定位输入与预期差异。

| 层次                   | 必要场景                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| 领域单元               | 状态转换、默认拒绝、范围/版本、幂等、证据充分性、复测三态、预算停止                       |
| 数据库/合约集成        | 同事务业务/审计/outbox、并发 CAS/唯一约束、迁移、权限、冻结报告、生成 client 合约         |
| Workflow / Runner 故障 | 重复事件、提交后未启动、lease 到期、旧 generation、未知结果、撤销/停止确认、历史 replay   |
| Web 组件与交互         | 真实 loading/empty/error/stale、命令受理查询、冲突输入保留、分页/批量范围、焦点及缓存隔离 |
| E2E / 交付             | 合成完整闭环、断线回补、授权出口旁路失败、OIDC/CSRF、对象访问、备份恢复与升级             |

测试使用合成数据、模拟服务及明确批准的内部环境；对外行为不得因运行测试意外连接真实目标。重要场景写明准备、操作和预期，可用 AAA 结构，不要求每条断言重复中文注释。时间、随机数、网络故障可控，不用固定 sleep 掩盖竞争。

必需集成 CI 缺 PostgreSQL、对象存储、Temporal 等依赖时失败；可选本地测试的 skip 明确标识，不能汇报为验证通过。Go race 用于适用并发包并在支持环境运行；Workflow replay 是额外兼容验证。覆盖率用于定位漏测，不能替代失败路径和业务不变量。axe-core 辅助检查后仍做实际键盘/读屏验证。

## 10. 文档、来源与变更记录

新增模块附中文 README：职责/边界、运行依赖、配置/秘密来源、接口/数据、状态不变量、本地验证、运维及兼容性。重大取舍用 ADR 记录问题、已知约束、方案、原因、代价和复核触发条件，不记录未经证实的性能提升。

注释与文档避免复制长状态机；核心枚举、转换规则、OpenAPI、能力目录各保留一个权威来源，其他位置引用并通过针对性检查避免漂移。配置样例只有占位符和默认拒绝值，不包含真实目标、账户或密钥。运维手册必须区分停止请求、确认、在途/未知、恢复与证据核对。

生成代码禁止手改，记录生成输入、工具版本、命令和检查方式；中文描述在 OpenAPI/schema 等源文件中维护再生成。第三方许可证/来源保留，ARTEX 代码复用前逐文件核对来源和许可；本规划继承行为不等于已批准直接复制。shadcn 是纳入维护的源码，不能将自持改动全标“generated”逃避审查。

提交建议 `type(scope): 中文说明`，如 `feat(execution): 增加命令受理结果查询`；机器需要的前缀保留，正文说明结果。PR 中文描述问题、行为变化、验证和兼容/风险，关联需求与验收；不列无意义历史流水。依赖升级、生成结果、纯格式整理与业务变化尽量可分别审查。

## 11. 工具门禁与完成定义

工具配置从一个锁定版本来源加载，编辑器、本地与 CI 一致。P0 首先建立规则，再创建代表模块验证。以下均为拟定门禁，骨架完成后在任务与 README 写入可实际运行的准确脚本；未配置前不得声称命令已通过。

| 自动检查                                               | 人工/场景检查                                      |
| ------------------------------------------------------ | -------------------------------------------------- |
| 编码/LF/末尾换行、格式、Go imports                     | 中文说明是否准确、是否说明业务原因而非翻译代码     |
| Go vet/lint、TS strict/typecheck、React Hooks/依赖边界 | 状态机、事务、幂等/取消/未知语义与设计是否一致     |
| 相关单元、真实依赖集成、race/replay                    | 并发冲突、出口约束、备份恢复与证据复核是否真实验证 |
| OpenAPI/sqlc 生成漂移、迁移兼容检查                    | 输入/错误/日志的数据分级、对象权限与原始证据边界   |
| Web build、关键 E2E、可访问性自动扫描                  | 键盘/焦点/读屏、中文术语、工作位置与误操作路径     |
| 依赖漏洞与秘密检测、来源/许可证检查                    | 误报处理、上游变更风险和文档/操作手册是否更新      |

中文语义、注释真实性和完整性不能由“每个文件包含汉字”的正则证明。工具可检查导出文档缺失、固定指令、过期 TODO 等结构问题，业务说明必须审查；忽略项精确到规则/位置并有中文原因。

一次业务提交完成需满足：行为符合对应需求/验收；相关契约、注释、生成结果、文档同步；变更所需格式/静态检查/测试通过；关键失败与并发路径有证据；秘密/权限/授权不越界；迁移/Workflow 兼容与回滚边界清楚。PR 明确列出未执行检查及原因，不将跳过、配置存在或静态阅读写成实测通过。
